# מצגת

המשתמש כנראה לא מתכנת. לדבר בעברית פשוטה, להריץ את הפקודות בעצמך, ולסכם במשפט מה קרה.

## 0. איזו מצגת?

- **פשוטה** (סעיף 1–4): קובץ אחד, מוכן תוך דקות, נשלח כ-PDF. מתאים לסיכום פגישה, הצעה קצרה, מצגת פנימית.
- **מרהיבה ב-open-slide** (סעיף 5–12): עיצוב במיתוג העסק, אנימציות, תמונות, מצב מציג עם הערות, וקישור שאפשר לשלוח. מתאים להרצאה, פגישת מכירה, מצגת ללקוח חשוב.

אם המשתמש כתב "מרהיבה", "מעוצבת", "open-slide", "עם קישור" או "להרצאה" — ישר למרהיבה. אם לא ברור — לשאול שאלה אחת: "פשוטה ומהירה ל-PDF, או מרהיבה עם קישור?"

**בשתיהן, התוכן קודם:** לקרוא את `business.md` אם קיים (שם, צבעים, פונט, טון, פרטי קשר). לשאול:
- **למי המצגת, ומה רוצים שהם יעשו בסוף?**
- **כמה זמן יש?** בערך שקופית לדקה או שתיים.

**להציג קודם רשימת שקופיות** — כותרת אחת לכל שקופית — ולקבל אישור לפני הבנייה.

**כללי שקופית (לשתיהן):**
- רעיון אחד לשקופית. עד 4 נקודות, כל נקודה עד שורה.
- כותרת שאומרת את המסקנה ("הלקוחות שלנו חוזרים — 70% מהם"), לא רק את הנושא ("לקוחות").
- מספר חשוב מקבל שקופית משלו, בגדול.
- שקופית אחרונה: מה מבקשים מהקהל לעשות.
- מחירים, מספרים, המלצות ושמות — רק מהמשתמש או מ-`business.md`. מה שחסר: `[למלא]`, לא להמציא.

# מצגת פשוטה

## 1. התוצר

`presentation.html` אחד בתיקיית פרויקט. כל שקופית היא `<section>`, עוברים ביניהן עם החצים, ושומרים כ-PDF דרך ההדפסה של הדפדפן.

## 2. בנייה

- `<html lang="he" dir="rtl">`, פונט עברי מ-Google Fonts, צבעים מ-`business.md`.
- כל שקופית `<section class="slide">` ביחס 16:9 (למשל 1280×720), ממורכזת ומוקטנת לגודל המסך.
- ניווט: חץ שמאלה או רווח = הבאה, חץ ימינה = הקודמת. מספר שקופית בפינה.
- הדפסה: `@media print` שבו כל שקופית היא עמוד (`@page { size: 1280px 720px; margin: 0 }`, `break-after: page`).
- טקסט גוף גדול מספיק לקריאה מהשורה האחרונה בחדר.

## 3. תמונות

אם צריך תמונות — להפעיל את הסקיל `images` (מהמאגר), ומה שאין במאגר — `ai-images`.

## 4. לבדוק ולמסור

- לפתוח בדפדפן ולעבור על כל השקופיות. לוודא ששום טקסט לא נחתך.
- להסביר למשתמש: חצים לניווט, F11 למסך מלא, Ctrl+P (או Cmd+P) → שמירה כ-PDF כדי לשלוח.

# מצגת מרהיבה ב-open-slide

open-slide הוא כלי חינמי שבו כל מצגת היא קוד, ו-Claude Code כותב אותו. רואים את התוצאה בדפדפן, מתקנים בהערות על השקופית, ומעלים לאוויר עם קישור.

## 5. הקמה — פעם אחת בלבד

לבדוק אם כבר קיים `~/my-business/slides/package.json`. אם כן — לדלג לסעיף 6.

אם לא (בחלונות: `%USERPROFILE%\my-business`):
```bash
cd ~/my-business
npx @open-slide/cli init slides
cd slides
npm install
```
- אם `npx` או `npm` לא נמצאים — להפעיל את הסקיל `setup` (מתקין Node.js), ולנסות שוב.
- אם ה-init שואל שאלות — לבחור את ברירות המחדל.
- **פרטיות:** ב-`open-slide.config.ts`, אם יש אפשרות `build.showSlideBrowser` — לקבוע `false`. כך מי שמקבל קישור למצגת אחת לא רואה את כל המצגות.
- ליצור `vercel.json` בתיקייה (בשביל ההעלאה לאוויר):
  ```json
  { "buildCommand": "npm run build", "outputDirectory": "dist", "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
  ```
- לוודא ש-`.gitignore` כולל `node_modules`, `dist`, `.env`.

להגיד למשתמש: "הקמתי את סביבת המצגות בתיקייה my-business/slides. מעכשיו כל מצגת נבנית שם."

## 6. להפעיל ולפתוח

מתוך `~/my-business/slides`, להריץ ברקע:
```bash
npm run dev
```
ולפתוח את הכתובת שמופיעה (בדרך כלל http://localhost:5173). להגיד למשתמש להשאיר את הלשונית פתוחה — כל שינוי יופיע בה מיד.

## 7. לקרוא את ההוראות של open-slide

ההקמה מתקינה סקילים של open-slide בתוך `~/my-business/slides/.claude/skills/`. **הם מקור האמת לאיך כותבים שקופית.** לפני שבונים, לקרוא:
- `slide-authoring/SKILL.md` — מבנה הקובץ, גודל הקנבס, גדלי טקסט.
- `create-theme/SKILL.md` — ערכת עיצוב (סעיף 8).
- `create-slide/SKILL.md` — בניית מצגת (סעיף 10).
- `apply-comments/SKILL.md` — תיקונים מהערות (סעיף 11).

לעבוד לפיהם. אם משהו בסקיל הזה סותר אותם — הם קובעים לגבי הקוד, והסקיל הזה קובע לגבי עברית, מיתוג ותהליך.

## 8. ערכת עיצוב של העסק — פעם אחת

אם אין עדיין קובץ ב-`themes/` שנקרא על שם העסק — ליצור אחד לפי `create-theme`, מתוך `business.md`:
- **צבעים** מ-`business.md` (ואם יש לוגו בתיקייה — לקחת ממנו את הצבע הראשי).
- **פונט עברי** מ-Google Fonts (Heebo, Rubik, Assistant או מה שכתוב ב-`business.md`).
- **עברית:** `dir="rtl"` לכל שקופית, יישור לימין. מילים באנגלית ומספרים בתוך `unicodeBidi: 'isolate'` כדי שלא יתבלגן הסדר.
- **הטון** מ-`business.md` קובע את האופי: עסק משפחתי חם → צבעים רכים, תמונות אמיתיות; עסק טכני → נקי ומדויק.

כך כל מצגת הבאה של העסק יוצאת במיתוג שלו, בלי להסביר מחדש.

## 9. תמונות

- תמונות אמיתיות של העסק — קודם (לבקש מהמשתמש לגרור תיקייה).
- מהמאגר — הסקיל `images`, בגודל `deck`.
- רקעים, אווירה ומה שאין במאגר — הסקיל `ai-images`, בגודל `deck`.
- לשמור ב-`slides/<מזהה-המצגת>/assets/` (כך `slide-authoring` מגדיר).
- **בלי אזורים ריקים:** כל שקופית מלאה — טקסט, תמונה או גרפיקה. מלבן ריק גדול = לתקן.

## 10. לבנות

לפי `create-slide`:
- **מזהה המצגת:** `<נושא-באנגלית>-<4 תווים אקראיים>`, למשל `sales-pitch-a7k2`. השם הזה יופיע בקישור.
- להשתמש בערכת העיצוב של העסק (סעיף 8).
- **הערות דובר** לכל שקופית: מה אומרים בה, בשפה מדוברת.
- אנימציות עדינות (כניסה של כותרת, הופעה של נקודות בזו אחר זו), לא קפיצות.

**לבדוק כל שקופית לפני שמראים:** לעבור על המצגת בדפדפן (בכתובת המצגת עם `?p=1`, `?p=2`...). אם יש כלי דפדפן או צילום מסך — לצלם כל שקופית ולהסתכל: טקסט שגולש או נחתך, טקסט מעל תמונה שלא קריא, שטחים ריקים, עברית שהסדר בה התבלגן. לתקן, ורק אז להראות למשתמש.

## 11. תיקונים

שתי דרכים:
- **בעברית:** "בשקופית 3 תגדיל את הכותרת ותחליף לתמונה אחרת" — ומתקנים.
- **בהערות על השקופית:** להסביר למשתמש ללחוץ **Inspect** בסרגל שמעל השקופית, לסמן אלמנט ולכתוב הערה. כשהוא כותב "סיימתי להעיר" — להפעיל את `apply-comments`.

## 12. להציג ולשתף

- **להציג:** כפתור **Present** — מסך מלא, חצים או רווח. **מצב מציג** (חלון עם הערות הדובר והשקופית הבאה): להוסיף `/presenter` בסוף הכתובת של המצגת.
- **PDF:** מכפתור הייצוא בממשק של open-slide.
- **קישור:** להפעיל את הסקיל `publish` מתוך `~/my-business/slides`. הקישור לשליחה הוא **`https://<שם-הפרויקט>.vercel.app/s/<מזהה-המצגת>`** — לא הכתובת הראשית. לבדוק שהוא נפתח בחלון גלישה בסתר ובטלפון.
- עדכון: כל תיקון → `publish` שוב, ואותו קישור מתעדכן.

**לסיים** בשלוש שורות: הקישור למצגת, איך פותחים מצב מציג, ואיך מבקשים מצגת חדשה בפעם הבאה ("תכין לי מצגת מרהיבה על...").
